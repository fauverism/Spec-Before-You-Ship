# Capability: astro-site-structure

## Requirement: Project is an Astro static site
The repository SHALL be structured as an Astro project with `astro.config.mjs`, `package.json`, and `src/` directory. The build output SHALL be a fully static set of HTML files with no server-side runtime.

### Scenario: Astro build succeeds
- **WHEN** `npm run build` is executed in the project root
- **THEN** Astro SHALL produce a `dist/` directory containing pre-rendered HTML for all pages with no build errors

### Scenario: No client JavaScript shipped by default
- **WHEN** any lesson page is loaded in a browser
- **THEN** no JavaScript bundle SHALL be fetched unless a component explicitly uses a `client:*` directive

## Requirement: Lesson pages use a shared layout component
All 11 lesson pages SHALL use a single `LessonLayout.astro` layout component that renders the page `<head>`, sidebar nav, mobile nav, and footer. Lesson-specific content SHALL be passed via Astro's `<slot />`.

### Scenario: Sidebar renders identically on every lesson
- **WHEN** any lesson page is loaded
- **THEN** the sidebar nav SHALL display all 11 lessons with correct titles, slugs, and lesson numbers, with the current lesson marked active

### Scenario: Lesson content is preserved verbatim
- **WHEN** a lesson page is rendered
- **THEN** the HTML inside the `<slot />` SHALL be output without modification, preserving all `<span class="t-*">` syntax highlighting and component markup

## Requirement: Sidebar nav is driven by a central data source
A single data file (`src/data/lessons.ts` or equivalent) SHALL define the ordered list of lessons with `{ num, slug, title }` for each. The `LessonLayout.astro` sidebar SHALL be generated by iterating this array.

### Scenario: Adding a lesson requires one data edit
- **WHEN** a new entry is appended to the lessons data array
- **THEN** the new lesson SHALL appear in the sidebar on all pages after the next build, with no changes to any layout or lesson page file

## Requirement: Lesson URLs use clean paths
Each lesson page SHALL be served at `/lessons/<slug>/` (e.g., `/lessons/02-install-and-init/`) with no `.html` extension in the URL.

### Scenario: Lesson page resolves at clean path
- **WHEN** a browser requests `/lessons/02-install-and-init/`
- **THEN** the server SHALL return the lesson 02 HTML page with HTTP 200

### Scenario: Old `.html` URL is not required
- **WHEN** a user navigates to `/lessons/02-install-and-init.html`
- **THEN** there is no guarantee of a redirect (breakage is acceptable for this migration)

## Requirement: Per-lesson styles use `is:global` scoping
Each lesson's `<style>` block SHALL use Astro's `is:global` attribute to prevent Astro from scoping class selectors, ensuring that class-based styles apply to slotted content HTML.

### Scenario: Token color classes apply to slotted content
- **WHEN** a lesson page is rendered and its `<style is:global>` block defines `.t-keyword { color: ... }`
- **THEN** `<span class="t-keyword">` elements inside the lesson content SHALL receive that color

## Requirement: Index and contact pages use a shared page layout
`index.html` and `contact.html` SHALL each be converted to `.astro` pages using a `PageLayout.astro` layout that provides the `<head>` and footer but not the lesson sidebar.

### Scenario: Index page renders without lesson sidebar
- **WHEN** the site index page (`/`) is loaded
- **THEN** the lesson sidebar SHALL NOT be present in the rendered HTML
